# Anime franchise catalog — implementation plan

## Status

Approved implementation plan for the [design proposal](anime-franchise-design.md). Implementation, verification, and local documentation are complete. AniList bulk import was not run; written permission remains required.

## Outcome

`!ima <franchise>` lists the current catalog characters in a franchise by name. `!imar <franchise>` lists the same distinct characters as `#rank - name`. Both use catalog rank order and local SQLite data. A franchise is a locally named group of AniList anime entries connected by selected relation types, with reviewer corrections. Anime metadata and every direct anime appearance of each current catalog character are saved for later game use.

## Ordered changes

1. **Prepare the catalog migration — `lib/catalogDb.js`.** Bump the SQLite schema version and add published and staging tables for anime metadata, character-anime appearances, typed anime relations, franchises, franchise membership, names/aliases, and saved reviewer corrections. Give anime their AniList IDs and franchises stable local IDs. Keep absent metadata nullable and store fetch/publication timestamps. Index anime IDs, character IDs, franchise membership, and searchable names. Preserve existing character, identity, marriage, and tag tables. Do not attach a cascading foreign key to `characters`: the current publication deletes and reinserts those rows. Validate character IDs while staging and join against current `characters` at lookup time. Check fresh database creation and migration of a version-3 fixture. Migration must roll back on failure.

2. **Expand the AniList client — `lib/anilistCatalogApi.js`.** Add paginated character-to-anime lookup by existing character ID. Retain enough media fields to apply the current character-eligibility check, but continue through every anime page for published characters. Add batched anime-detail and relation queries for the approved field set: AniList ID, title variants, synonyms, genres, tags, start date, season year, format, status, average score, popularity, adult flag, cover image, and URL. Ask for typed relation edges and anime node IDs/types. AniList documents `COMPILATION` as version 2 only and `SAME_UNIVERSE` as version 3 only, so the client requests both relation versions and prefers version 3 when both provide a value. Reuse request spacing, timeout, 429 handling, and retry logic. Mock all API responses in tests; do not make live bulk requests during development.

3. **Build a separate, resumable enrichment import — new `scripts/importFranchiseCatalog.js` and focused helpers in `lib/franchiseCatalog.js`.** Start from IDs in the *published* character catalog after its import completes. Fetch every anime appearance for each current character, deduplicate anime IDs, then fetch media details and relation edges. Follow only approved anime-to-anime edge types to reach intermediate anime needed to connect groups; track visited IDs to avoid loops. Keep other relation types as source evidence without using them to join groups. Checkpoint by completed character/media batch, never by an incomplete page. Stage source facts and report counts, coverage, missing/deleted entries, and start/end times. Fail without replacing the published franchise view if data is incomplete. Require `--permission-confirmed` after AniList's written grant, matching the existing importer. Run this enrichment after each character-catalog refresh; record the source character-catalog publication token and refuse player lookups when the franchise view is stale.

4. **Generate and reconcile franchises — `lib/franchiseCatalog.js` and `lib/catalogDb.js`.** Build connected components from anime-only `PREQUEL`, `SEQUEL`, `PARENT`, `SIDE_STORY`, `SPIN_OFF`, `ALTERNATIVE`, `SUMMARY`, and `COMPILATION` links. Leave unlinked anime as one-member franchises. Exclude `CHARACTER`, `SAME_UNIVERSE`, `OTHER`, and cross-media source/adaptation links from automatic grouping. Choose an initial display name from a representative member, favoring a popular TV anime; index member titles and synonyms as search aliases. Reconcile new groups with stable local franchise IDs, then apply saved reviewer names, aliases, merges, and member moves/removals. Report automatic merges/splits for review. Publish the new searchable snapshot in one transaction so failed import or grouping leaves the prior view intact.

5. **Add a local correction page — new `scripts/reviewFranchises.js` and `scripts/reviewFranchises.html`; `package.json`.** Reuse the tag-review server's localhost default, host checks, request-size limits, and no-cache responses. Show a franchise's members, source relation types, and current character count. Support rename, add/remove alias, merge groups, create a group for a split, and move/remove an anime. Show generated changes and saved manual decisions separately. Validate IDs and text on the server, apply edits transactionally, and preserve them on the next enrichment run. Add one explicit npm command for this page and one for the permission-gated enrichment importer. Merge these small script edits with the user's current `package.json` changes.

6. **Add local lookup logic — new `lib/franchiseLookup.js`.** Search display names, manual aliases, and member anime titles/synonyms using normalized exact match first, then prefix and substring matches. Return distinct franchise candidates in a stable order. Query character IDs through franchise membership and direct appearances, join to current `characters`, deduplicate by AniList character ID, and order by catalog rank. Provide a clear no-data/stale-snapshot result rather than silently returning partial results.

7. **Add two prefix commands — new `commands/ima.js`, `commands/imar.js`, and a shared renderer under `commands/utils/`; `index.js`.** Add `ima` and `imar` to the existing character-game command dispatch. Do not register slash commands. Let the user choose a franchise when several match. Paginate long character lists with Components V2 and the existing one-hour interaction pattern. Keep `!ima` name-only throughout the result UI; show `#rank - name` in `!imar`. Escape names, prevent mentions, and keep controls limited to the requesting user. Reuse `!char`'s paging pattern without refactoring its behavior.

8. **Document operation — `docs/character-catalog.md` and this design/plan pair.** Add the enrichment sequence, written-permission prerequisite, restart behavior, stale-view message, correction-page workflow, and limits of AniList relations. Keep current user edits in `docs/character-catalog.md` intact. State that AniList franchise labels are local game data and may require review.

## Implementation and verification

Implemented the migration, paginated AniList enrichment, relation-based local grouping, saved correction workflow, `!ima` and `!imar` prefix commands, operational docs, and focused tests. Verified the new catalog, command, and review tests plus the catalog type check. The repository's complete test suite was also run file-by-file because the default Node test runner cannot spawn workers in this environment. No live AniList bulk call was made; written permission remains required.
